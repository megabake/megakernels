# megakernels

Decode megakernels generated by [MegaBake](https://github.com/megabake/megabake). Each one
is a whole decode step, compiled from `torch.compile`'s FX graph into a single persistent
CUDA kernel (CuTe DSL).

**How to read it.** Decode, batch 1, bf16, one token per call into a static 128-token KV
cache. Each time is the median complete call (host and GPU, CUDA events around the call).
Speedup is *torch.compile + CUDA graph time ÷ MegaBake time*, so values above 1× mean
MegaBake is faster. *MIG 3g.71gb* is a 3/7 slice of one H200.

- **torch.compile + CUDA graph**: `torch.compile(model, fullgraph=True)` with the whole
  decode step captured into one `torch.cuda.CUDAGraph`, or Inductor's
  `mode="reduce-overhead"` where that was faster.
- **Launches**: kernel launches per call, torch.compile + CUDA graph → MegaBake.

## Layout

```
kernels/<org>--<model>/<gpu>/<mode>/
    module.py          the generated kernel (CuTe DSL Python)
    source_map.json    kernel source → FX node mapping
    report.json        the benchmark it came from
archive/<run>/...      every benchmark run so far: report.json and module.py per mode
```

The archive holds 51 kernels from 49 benchmark runs. Each published
`report.json` records its source artifact, measurement time and `megabake_commit`: the
newest MegaBake commit at that time. The working tree may have had changes on top of it.

## Using a kernel

Kernels import `megabake.runtime` and MegaBake's CuTe bodies, so they run against the MegaBake
revision that generated them (`8b94b7c` for the table above).
To regenerate one on your own GPU:

```sh
git clone https://github.com/megabake/megabake && cd megabake
python benchmarks/full_model.py --model Qwen/Qwen2-0.5B --modes decode --out out/
```
